# План оптимизации архитектуры DOCs_Macros

## Текущее состояние

| Файл | Строк | Проблема |
|------|-------|----------|
| `XMIgenerator.cs` | ~1950 | Монолитный класс, смешивает UI, бизнес-логику и генерацию XMI |
| `SchemaFetcher.cs` | ~350 | Дублирует логику чтения свойств структуры из `XMIgenerator.cs` |
| `ApiDumper.cs` | ~150 | Относительно чистый, но нет единых утилит |
| `Program.cs` | ~70 | Простой switch-case dispatcher |

## Ключевые проблемы

1. **XMIgenerator.cs — монолит (~1950 строк)**: один класс `XmiSchemaExporterMacro` содержит UI-диалоги, рефлексию API DOCs, бизнес-логику связей и генерацию XMI+EA extension.
2. **Отсутствие разделения ответственности (SRP)**: `Run()` делает выбор каталогов → выбор связей → построение модели → генерацию XMI.
3. **Массовая рефлексия**: `GetPropertyValue()`, `GetEnumerableProperty()`, `TryAddReferencePicker()` — дублируются и используются без кэширования.
4. **Нет интерфейсов**: невозможно тестировать логику независимо от API DOCs.
5. **Дублирование**: `AddStructureSettings()` в `XMIgenerator.cs` и `ExportReferenceSchema()` в `SchemaFetcher.cs` читают одни и те же свойства структуры.
6. **Жёстко закодированные строки**: русские названия настроек, подписи диалогов, mapping типов — всё в теле метода.
7. **Нет кэширования рефлективных вызовов**: каждый вызов `GetProperty().GetValue()` делает рефлексию заново.

## Пошаговый план

### Этап 1: Извлечение модели и утилит (без изменения поведения)

**Цель**: Создать фундамент без риска регрессии.

1. **`Core/DeterministicGuid.cs`** — вынести `CreateDeterministicGuid()`, `FormatEaId()`, `FormatMultiplicity()`.
2. **`Core/ReflectionCache.cs`** — кэш `GetProperty()`/`GetMethod()` результатов. Заменить все `GetPropertyValue()` на `IDocsApi.GetPropertyValue()`.
3. **`Model/`** — переместить все `*Model` классы (`ClassModel`, `ParamModel`, `AssocModel`, `CatalogModel`, `EventModel`, `SelectedCatalogContext` → `SelectedCatalog`, `SelectedRelation`, `CatalogRelationItem`) в отдельные файлы.
4. **`Config/StructureSettings.cs`** — вынести массив `structureSettings` из `AddStructureSettings()` в конфигурационный класс.

### Этап 2: Абстракция API DOCs

**Цель**: Отделить работу с DOCs API от бизнес-логики.

5. **`Core/IDocsApi.cs`** — интерфейс:
   ```csharp
   interface IDocsApi {
       ReferenceInfo FindReference(string name);
       ReferenceInfo[] GetAllReferences();
       object GetPropertyValue(object source, string propertyName);
       IEnumerable<object> GetEnumerableProperty(object source, string propertyName);
       IEnumerable<ParameterGroup> GetLinksFromOwner(object owner);
       ReferenceInfo GetSlaveReference(ParameterGroup link);
       bool IsTrue(object value);
       // ... и т.д.
   }
   ```
6. **`Core/DocsApiAdapter.cs`** — реализация через рефлексию (оборачивает текущую логику `GetPropertyValue`, `TryAddReferencePicker`, `GetSlaveReference` и т.д.).
7. Заменить все прямые вызовы API в сервисах на `IDocsApi`.

### Этап 3: Разбиение `Run()` на сервисы

**Цель**: Разделить монолит `Run()` на отдельные шаги.

8. **`Services/CatalogSelectionService.cs`** — извлечь цикл `while(true)` из `Run()`, `SelectReference()`, `SelectObjectTypes()`, `SelectParameters()`, `ShowParameterSelectionDialog()`, `BuildAddMoreTypesPrompt()`.
   - Ответственность: получить `List<SelectedCatalog>`.
9. **`Services/RelationService.cs`** — извлечь `SelectRelations()`, `CatalogRelationItem`, `GetRelationNameForCatalog()`.
   - Ответственность: получить `List<SelectedRelation>`.
10. **`Services/ModelBuilderService.cs`** — извлечь `BuildClasses()`, `BuildCatalog()`, `BuildEvents()`, `IsParameterAttachedToType()`, `IsLinkAttachedToMasterClass()`, `IsLinkAllowedForSlaveClass()`, `AddComplexHierarchyAssociations()`, `AddIntraCatalogHierarchyAssociations()`, `GetAssociationMultiplicity()`, `MapType()`.
    - Ответственность: получить `ExportContext` (полная UML-модель).

### Этап 4: Генерация XMI

**Цель**: Отделить XML-генерацию от построения модели.

11. **`Generators/IXmlGenerator.cs`** — интерфейс `GenerateXmi(ExportContext context)`.
12. **`Generators/UmlXmiGenerator.cs`** — извлечь весь код от создания `pkg` до `doc.Save()`: `CreateProperty()`, `CreateCatalogTypeAssociation()`, `CreateSignal()`, `CreateOwnedEnd()`, `AddOwnedComment()`, `AddTags()`, `BuildStereotypeApplications()`, `CreateCustomProfile()`, `AddProfileStereotype()`.
13. **`Generators/EaExtensionGenerator.cs`** — извлечь `BuildEaExtension()`, `CreateEaProjectMetadata()`.
14. **`Services/XmiGenerationService.cs`** — координация: `ModelBuilderService` → `UmlXmiGenerator` + `EaExtensionGenerator` → сохранение файла.

### Этап 5: Устранение дублирования с SchemaFetcher

**Цель**: Единый источник правды для настроек структуры.

15. Использовать `Config/StructureSettings.cs` и `Core/IDocsApi` в `SchemaFetcher.cs` вместо дублирующегося кода чтения свойств.
16. Вынести `ToIdentifier()`, `GetUniqueIdentifier()` в `Core/StringUtils.cs`.

### Этап 6: Финальная полировка

17. Добавить XML-комментарии для всех публичных методов сервисов.
18. Убрать `static` из методов, которым не нужен контекст (например, `GetPrimaryGroupGuid` → instance method).
19. Добавить `ArgumentNullException` проверки для публичных API сервисов.
20. Проверить сборку: `dotnet build`.

## Риски и митигация

| Риск | Митигация |
|------|-----------|
| Рефлексия DOCs API ломается на разных версиях | `DocsApiAdapter` содержит все try/catch — тестировать на целевой версии DOCs 18 |
| Регрессия в XMI-формате | После каждого этапа сравнивать выходной .xml с эталонным |
| Breaking change для загрузчика макросов DOCs | `XmiSchemaExporterMacro` остаётся entry-point, просто делегирует сервисам |

## Верификация

1. **Сборка**: `dotnet build` без ошибок и предупреждений (кроме существующих MSB32xx).
2. **Сравнение XMI**: запустить макрос до и после рефакторинга на одном и том же наборе справочников, сравнить выходные XML через `diff`.
3. **Функциональное тестирование**: проверить все шаги выбора (каталог → типы → параметры → подключение → связи) и сохранение файла.
4. **SchemaFetcher**: убедиться, что `dotnet run -- schema` выдаёт те же `.md`/`.cs` файлы.
